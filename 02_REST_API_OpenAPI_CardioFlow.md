# Спецификация REST API интеграционного шлюза «Кардио-Поток»

**Версия документа:** 1.0.0  
**Стандарт спецификации:** OpenAPI 3.0.3  
**Оператор информационной системы:** КГБУЗ «Алтайский краевой кардиологический диспансер» (АККД)

---

## 1. Общие сведения и архитектура шлюза

Интеграционный шлюз **«Кардио-Поток»** представляет собой программный интерфейс взаимодействия между медицинскими информационными системами (МИС) районных поликлиник Алтайского края и региональным сегментом единой государственной информационной системы в сфере здравоохранения (ЕГИСЗ) на базе КГБУЗ «АККД».

### Ключевые архитектурные параметры

- **Назначение API.** Автоматизация межведомственной маршрутизации пациентов, предварительного бронирования слотов расписания и передачи электронных направлений на консультативный прием к врачам-кардиологам краевого уровня.
- **Базовый URL (Production).** `https://akkd-barnaul.ru`
- **Сетевой и транспортный протоколы.** Взаимодействие осуществляется исключительно по защищенному протоколу `HTTPS` (TLS версии 1.2 и выше с использованием сертифицированных средств криптографической защиты информации).
- **Формат обмена данными.** `application/json` с обязательной кодировкой символов `UTF-8`. Все HTTP-запросы, передающие тело сообщения, должны содержать заголовок `Content-Type: application/json; charset=utf-8`.

## 2. Механизм аутентификации и информационной безопасности

Доступ к ресурсам шлюза регламентируется требованиями законодательства Российской Федерации в области защиты персональных данных и врачебной тайны.

### Аутентификация и авторизация

Аутентификация клиентских систем (МИС районных медицинских организаций) выполняется на основе токенов доступа формата **JSON Web Token (JWT)** по схеме `Bearer Authentication`.

- Токен передается в каждом HTTP-запросе внутри стандартного заголовка `Authorization`.
- Формат заголовка: `Authorization: Bearer <access_token>`.
- Срок жизни токена (TTL) составляет 3600 секунд. По истечении указанного времени сервер возвращает статус `401 Unauthorized`, требующий повторного получения токена через сервер авторизации.

### Нормативные требования по защите данных

Программный интерфейс спроектирован с учетом обязательных мер защиты информации ограниченного доступа:

- **Федеральный закон № 152-ФЗ «О персональных данных».** Передача специальных категорий персональных данных (сведений о состоянии здоровья) осуществляется по зашифрованным каналам связи с применением российских криптографических алгоритмов (ГОСТ Р 34.10-2012, ГОСТ Р 34.11-2012) через сертифицированные криптошлюзы.
- **Федеральный закон № 323-ФЗ «Об основах охраны здоровья граждан в Российской Федерации» (ст. 13).** Доступ к методам API предоставляется только авторизованным медицинским организациям, внесенным в Федеральный реестр медицинских организаций (ФРМО), при наличии подписанного информированного добровольного согласия пациента и согласия на обработку персональных данных в МИС-отправителе.
- **Аудит и журналирование.** Все входящие запросы, включая идентификатор направляющей организации (`clinic_oid`), временную метку и результат обработки, фиксируются в защищенном журнале аудита для обеспечения неотказуемости и контроля доступа к врачебной тайне.

## 3. Спецификация эндпоинтов

### 3.1. Создание электронной записи на прием к кардиологу

Регистрирует заявку на первичный или повторный прием пациента в КГБУЗ «АККД» и резервирует временной слот в расписании специалиста.

- **Метод:** `POST`
- **Путь:** `/api/v1/appointments`
- **Требуемые права (Scope):** `appointments:write`

#### Параметры тела запроса (Request Body)

|Параметр|Тип данных|Обязательность|Правила валидации и описание|
|---|---|---|---|
|`patient_snils`|`string`|**Required**|Страховой номер индивидуального лицевого счета пациента. Строгий формат: `^\d{3}-\d{3}-\d{3} \d{2}$` (14 символов, включая дефисы и пробел). Проходит проверку контрольного числа.|
|`full_name`|`string`|**Required**|Фамилия, имя и отчество пациента (при наличии) в именительном падеже. Допустимы символы кириллицы, пробелы и дефис. Длина от 5 до 150 символов.|
|`icd10_code`|`string`|**Required**|Код основного диагноза по Международной классификации болезней 10-го пересмотра (МКБ-10). Регулярное выражение: `^[I][0-9]{2}(\.[0-9]{1,2})?$` (класс IX — болезни системы кровообращения).|
|`preferred_date`|`string`|**Required**|Желаемая дата планового приема в формате стандарта ISO 8601 (`YYYY-MM-DD`). Дата должна быть больше текущей даты минимум на 1 рабочий день и не превышать горизонт планирования (30 календарных дней).|
|`clinic_oid`|`string`|**Required**|Уникальный идентификатор направляющей медицинской организации в справочнике ФРМО (OID). Формат: `^1\.2\.643\.5\.1\.13\.13\.12\.2\.22\.\d{1,6}$`.|

### 3.2. Проверка доступных квот на диагностику

Метод предназначен для получения актуального перечня свободных временных слотов (талонов) на проведение инструментальных и функциональных диагностических исследований (эхокардиография — ЭхоКГ, холтеровское мониторирование ЭКГ — Холтер, суточное мониторирование артериального давления — СМАД) в выбранном структурном подразделении КГБУЗ «АККД» на заданную календарную дату.

- **Метод:** `GET`
- **Путь:** `/api/v1/quotas/{department_id}`
- **Требуемые права (Scope):** `quotas:read`

#### Параметры пути (Path Parameters)

|Параметр|Тип данных|Обязательность|Правила валидации и описание|
|---|---|---|---|
|`department_id`|`string` (`uuid`)|**Required**|Уникальный идентификатор диагностического отделения КГБУЗ «АККД» в формате UUID v4 (`^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$`).|

#### Параметры строки запроса (Query Parameters)

|Параметр|Тип данных|Обязательность|Правила валидации и описание|
|---|---|---|---|
|`date`|`string` (`date`)|**Required**|Целевая дата проведения диагностического исследования в формате стандарта ISO 8601 (`YYYY-MM-DD`). Значение должно находиться в пределах открытого горизонта расписания (от `T+1` до `T+30` календарных дней).|

#### Пример HTTP-запроса

http

```
GET /api/v1/quotas/4a7d1e90-8b2c-4f3a-9e1d-6c5b4a3f2e1d?date=2026-11-19 HTTP/1.1
Host: akkd-barnaul.ru
Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9.eyJpc3MiOiJha2tkLWF1dGgiLCJzdWIiOiJtaXMtYml5c2stMDEiLCJzY29wZSI6InF1b3RhczpyZWFkIiwiZXhwIjoxNzk0Mzk2MDAwfQ.signature_payload_example

```

#### Обработка бизнес-ошибки: исчерпание квот (409 Conflict)

В случае если на запрашиваемую дату все выделенные межведомственные квоты для направляющей медицинской организации распределены или расписание подразделения закрыто, сервер возвращает статус `409 Conflict` с детальным описанием бизнес-исключения.

http

```
HTTP/1.1 409 Conflict
Content-Type: application/problem+json; charset=utf-8

{
  "type": "https://akkd-barnaul.ru",
  "title": "Квоты на выбранную дату исчерпаны",
  "status": 409,
  "detail": "На дату 2026-11-19 в отделении 4a7d1e90-8b2c-4f3a-9e1d-6c5b4a3f2e1d отсутствуют доступные для бронирования слоты.",
  "instance": "/api/v1/quotas/4a7d1e90-8b2c-4f3a-9e1d-6c5b4a3f2e1d",
  "error_code": "ERR_QUOTA_EXHAUSTED",
  "nearest_available_date": "2026-11-23"
}
```

### 3.3. Сводная таблица кодов ответа HTTP (Status Codes)

Взаимодействие с ресурсами интеграционного шлюза «Кардио-Поток» опирается на стандартную семантику кодов состояния протокола HTTP/1.1.

|Код состояния|Статус HTTP|Описание и сценарий возникновения в шлюзе|
|---|---|---|
|`200`|**OK**|Запрос успешно выполнен. Возвращается при получении актуального списка свободных квот или статусов направлений.|
|`201`|**Created**|Ресурс успешно создан. Возвращается при подтверждении электронной записи пациента на прием к врачу-кардиологу.|
|`400`|**Bad Request**|Ошибка синтаксиса или форматно-логического контроля. Возникает при неверном формате UUID, даты, кода МКБ-10 или несовпадении контрольного числа СНИЛС.|
|`401`|**Unauthorized**|Ошибка аутентификации. Заголовок `Authorization` отсутствует, имеет неверный формат или срок действия токена Bearer JWT истек.|
|`403`|**Forbidden**|Доступ запрещен. Токен действителен, но у клиента отсутствуют требуемые права (`scope`) либо OID организации заблокирован в реестре шлюза.|
|`409`|**Conflict**|Конфликт бизнес-логики. Возникает при попытке записи на занятый слот, при полном исчерпании квот на дату или дублировании активного направления.|
|`500`|**Internal Server Error**|Внутренняя ошибка сервера. Непредвиденный сбой на стороне интеграционного шлюза или недоступность шины данных регионального сегмента ЕГИСЗ.|
